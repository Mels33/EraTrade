# Регламент живой торговли (этап 14 — ручное подтверждение)

Аккаунт: основной (решение 2026-11-17, без субаккаунта). Лимиты: номинал ≤ 20 USDC,
плечо 2x isolated, дневной убыток ≤ 2% equity, недельный ≤ 5%, ≤ 4 сделок в день.
Каждый ордер подтверждается оператором в терминале.

Переменные окружения для команд ниже:

```bash
export ERATRADE_ENV_FILE=.env.mainnet,.env.mainnet.secrets   # команды с ключом
```

## 1. Перед включением (один раз и после любых изменений)

1. `uv run eratrade live-check` — **ни одного FAIL**. Разобрать каждый WARN.
2. `uv run eratrade notify-test` — сообщение пришло в Telegram (бот `@my_new_era_trade_ai_bot`,
   сначала нажать Start).
3. **Учебный kill switch** (без позиции): `uv run eratrade kill -r "учения перед live"` →
   позиция и ордера проверены, режим стал DISABLED. Вернуть: `uv run eratrade set-mode LIVE_PAUSED -r "после учений"`.
4. **Проверка восстановления БД**: `scripts/restore_check.sh backups/<последний eratrade_mainnet_*.dump>`
   (результат пишется в `backups/restore_checks.log`, его видит `live-check`).
5. Модель: в shadow накоплены доказательства (`uv run eratrade shadow-report`,
   требования — секция `[live]` в `config/strategy.toml`). Активация:
   `uv run eratrade model-activate <версия> -r "..."`. Без доказательств команда откажет.

## 2. Включение

```bash
uv run eratrade set-mode LIVE_ENABLED -r "этап 14: ручное подтверждение"   # спросит фразу подтверждения mainnet
uv run eratrade trader            # в отдельном терминале (tmux/screen), не закрывать
```

`trader` делает проход через 5 с после закрытия каждой часовой свечи. При старте процесса
LIVE_ENABLED прошлого запуска понижается до LIVE_PAUSED (с уведомлением) — включать снова вручную.

## 3. Подтверждение ордера — что проверить в превью (§17.2)

- сторона и размер соответствуют сигналу; номинал ≤ 20 USDC;
- **убыток до стопа** не больше «риск на сделку»;
- цена стопа по правильную сторону от рынка (long — ниже, short — выше);
- спред ≤ 5 bps; позиция сейчас — та, что ожидалась.

Ответ позже 60 с — ордер не отправится (цена устарела). Если рынок сдвинулся больше
10 bps между превью и отправкой, движок сам заблокирует вход.

## 4. После каждой сделки

`uv run eratrade trades` (или карточка «Сделки» в панели):

- `✓ размер и стоп в порядке` — нет несоответствий;
- комиссии и funding совпадают с биржей; нетто = PnL биржи − комиссии + funding;
- проскальзывание входа против превью и против close свечи сигнала — в пределах 10 bps;
- выход: `exit` (по сигналу/времени), `stop` (сработал защитный стоп), `manual` (вручную).

Любой `✗` — пауза (`uv run eratrade pause -r "..."`) и разбор до продолжения.

## 5. Аварийные действия

| Ситуация | Действие |
|---|---|
| Что-то непонятно, нужно остановить входы | `eratrade pause -r "..."` (ключ не нужен) или кнопка «Пауза» в панели |
| Закрыть позицию | `eratrade flatten` или «Закрыть позицию» в панели (подтверждение `FLATTEN`) |
| Полная остановка | `eratrade kill -r "..."` или kill switch в панели (`KILL`): пауза → закрыть → отменить ордера → DISABLED |
| Бот/сервер недоступен | закрыть позицию вручную в интерфейсе Hyperliquid; защитный стоп уже стоит на бирже. После восстановления сверка увидит ручное закрытие сама |
| Сверка нашла критичное расхождение | входы блокируются автоматически; разобрать (`eratrade reconcile`, `eratrade orders`), затем `eratrade unblock -r "..."` |
| Сработал лимит убытка | входы заблокированы до решения оператора; разобрать, `eratrade unblock -r "..."` не раньше следующего дня |
| PostgreSQL потерян | остановить `trader`; восстановить последний дамп (`pg_restore` в чистую БД), `alembic upgrade head`, затем `eratrade reconcile` — fills и ордера подтянутся с биржи |

## 6. Ежедневно

- панель: компоненты зелёные, сверка ok, свечи свежие;
- `eratrade risk-status` — дневной/недельный PnL против лимитов;
- `eratrade shadow-report --days 1` — ошибок нет, дрейф признаков < 1σ;
- бэкап за сутки есть (`live-check`).

## 7. Переход к этапу 15 (автоматическое исполнение)

Только когда на ручном этапе одновременно:

- не меньше 10 закрытых сделок без единого `✗` в разборе;
- ни одного дубля ордера и неучтённого fill (сверка ok всё время);
- проскальзывание и комиссии в пределах заложенных в target (14.5 bp туда-обратно);
- восстановление после рестарта `trader` проверено вживую;
- результаты не хуже shadow (нет деградации модели).

## 8. Этап 15 — автоматическое исполнение (§17.3)

Включается только после раздела 7. Два явных изменения в `config/strategy.toml`:

```toml
[execution]
require_manual_confirmation = false
[auto]
enabled = true
```

Запуск (Docker, профиль `live`, без автоперезапуска):

```bash
scripts/eratrade.sh auto-start     # спросит слово AUTO; процесс сам проверит барьер
uv run eratrade set-mode LIVE_ENABLED -r "этап 15"   # торговля начинается только в этом режиме
scripts/eratrade.sh auto-stop      # остановить (позиция остаётся под биржевым стопом)
```

Барьер `trader --auto` (процесс завершится с причинами, если не пройден):
`auto.enabled`, ручное подтверждение выключено, `live-check` без FAIL, не меньше
`auto.min_manual_trades` (10) закрытых сделок бота и ни одной с замечаниями разбора.

Что бот делает сам:

- одна позиция, минимальный размер, без увеличения и разворота (guard и политика);
- **автопауза** (LIVE_ENABLED → LIVE_PAUSED + запрет входов + уведомление) при любом
  неисправленном расхождении сверки (warning и critical), ошибке исполнения или замечании
  в разборе только что закрытой сделки; выходы и стопы продолжают работать;
- после любого рестарта процесса режим понижается до LIVE_PAUSED — торговлю снова
  включает только оператор; контейнер `trader-mainnet` после падения не перезапускается;
- `scripts/eratrade.sh down` останавливает и автоматический trader.

После автопаузы: разобрать причину (`eratrade trades`, `eratrade reconcile`, логи
`scripts/eratrade.sh logs trader-mainnet`), затем `eratrade unblock -r "..."` и
`eratrade set-mode LIVE_ENABLED -r "..."`.

Расширение лимитов (§17.4) — по одному изменению за раз (размер, число сделок, рынки),
только после подтверждения: нет дублей и неучтённых fills, стабильное исполнение,
издержки в пределах заложенных, достаточно наблюдений, приемлемая просадка, нет деградации модели.
