# EraTrade

Маркет-мейкер для Hyperliquid: post-only (ALO) заявки с обеих сторон стакана на монетах с
положительным edge после комиссий и adverse selection, скос по позиции и потоку агрессивных
сделок. Минимальный
капитал: заявка 12 USDC, позиция ≤ 25 USDC на монету, дневной убыток ≤ 2 USDC.
История решений: `План_разработки_AI-торгового_бота_Hyperliquid.md`.

## Запуск

```bash
scripts/eratrade.sh up        # БД + API с панелью + бэкапы (Docker)
scripts/eratrade.sh mm-start  # маркет-мейкер с живыми заявками (котирует в режиме «Торгует»)
scripts/eratrade.sh mm-stop   # остановить маркет-мейкер (заявки снимаются, позиция остаётся)
scripts/eratrade.sh status    # контейнеры и сводка
scripts/eratrade.sh logs mm-mainnet
scripts/eratrade.sh down      # остановить всё (данные БД сохраняются)
```

Нужны `.env.mainnet` и `.env.mainnet.secrets` (ключ API-кошелька и `API_TOKEN`; ключ читает
только маркет-мейкер). Панель: http://127.0.0.1:8000, вход — `API_TOKEN`.

## Панель

- **Торговля** — статус, результат за сутки, график накопленного результата, лимит убытка,
  расход действий и запросов; по каждой монете — цена, спред, наши заявки, позиция, поток
  сделок, итог дня; сделки и итоги по дням.
- **Система** — режим, сервисы, журнал действий.
- **Управление** — «Запустить торговлю» (фраза `I_UNDERSTAND_REAL_MONEY`), «Пауза» (заявки
  снимаются, позиция остаётся), «Остановить и закрыть позиции» (`STOP`).

## Маркет-мейкер

Конфигурация — `config/strategy.toml`, секция `[mm]` (монеты, размер заявки, пределы,
пороги спреда и потока, бюджет действий). Выбор монет:

```bash
ERATRADE_ENV_FILE=.env.mainnet uv run eratrade mm-scan   # спред, adverse selection, edge, оборот
```

Правила котирования (`app/mm/quoter.py`): стакан без своих заявок; справедливая цена —
середина спреда, сдвинутая против позиции (`inventory_skew_bps` при полной позиции); заявка не
ближе `min_edge_bps` от неё (круг ≥ 2 × 3 bp при комиссиях 3 bp), в этих пределах — как можно
ближе к рынку; спред уже `min_spread_bps` — новую позицию не набирать, держать только
reduce-only заявку на закрытие; сторона сверх предела позиции не котируется; сильный перекос
потока сделок снимает сторону против него; заявка в пределах `requote_slack_bps` не
переставляется. Защита (`app/mm/maker.py`): котирует только в `LIVE_ENABLED` без запрета
входов; дневной убыток → снять заявки, закрыть позиции, запретить входы; устаревший стакан →
снять котировки; бюджет действий в минуту и резерв лимита запросов адреса; сверка заявок и
позиции с биржей каждые 5 с. `scheduleCancel` биржа даёт только после оборота $1 млн — до
этого при выключении компьютера заявки остаются на бирже.

## Исторический тест маркет-мейкера

Тест использует события L2 и публичные сделки, а не минутные свечи:

```bash
uv run eratrade mm-backtest COIN \
  --book data/mm/COIN_l2.jsonl --trades data/mm/COIN_trades.jsonl \
  --sz-decimals 2 --markouts 1,5,30,60 --selection-horizon 30
```

`--book` принимает JSONL с сообщениями `l2Book` (включая обёртку WebSocket `data`), `--trades` —
JSONL со сделками или объектами `fills`; оба параметра можно повторять для нескольких файлов.
Записи в каждом файле должны идти по времени. Без `--sz-decimals` точность размера запрашивается
из Hyperliquid `meta`. Комиссия, задержка выставления и путь результата настраиваются через
`--maker-fee-bps`, `--latency-ms` и `--out`.

Заявка встаёт за объёмом существующего уровня. Очередь уменьшают только сделки; исчезнувший из
снимка объём считается возможной отменой и не продвигает заявку. Сделка сквозь цену исполняет
остаток. Результат включает частичные исполнения, позицию, реализованный и нереализованный PnL,
комиссии, оборот и max drawdown. Это консервативная приближённая модель очереди, а не точное
восстановление по order id.

Markout — знаковое изменение середины спреда после исполнения. Отрицательный средний markout
сохраняется в `data/mm/adverse_selection.json` как penalty. `mm-scan` и автовыбор загружают файл
из `mm.adverse_selection_path` и считают `edge = спред − 3 bp комиссий − 2 × adverse selection`;
монета с неположительным edge отбрасывается. Без файла penalty равен нулю, поэтому перед живым
выбором нужен реальный исторический тест.

Исторические L2 и сделки: [официальный архив Hyperliquid](https://hyperliquid.gitbook.io/hyperliquid-docs/historical-data)
(`market_data/.../l2Book` и `node_fills`; доступ requester-pays). Архив автоматически не
скачивается.

## Исследование «спрос и предложение»

```bash
uv run eratrade micro-data --since 2023-01-01        # архив Binance → минутные строки
uv run eratrade walk-forward-micro --model flow      # поток сделок (история с 2023)
```

Горизонт часы — 1–2 дня (`uv run eratrade sd-research --idea all`, кварталы 2024–2026,
параметры выбираются на 12 предыдущих месяцах): зоны «база → импульс» −0.22% на сделку
(t = −2.6, цена чаще пробивает зону, чем отскакивает), дисбаланс покупок/продаж за дни −0.26%,
асимметрия стакана ±1–5% −0.01% (лучше случайного входа −0.13%, но t ≈ 0) — ворота не прошла
ни одна идея.

Поток и стакан предсказывают цену на 1–15 мин статистически значимо, но выигрыш 1–3 bp — в
3–10 раз меньше издержек направленной торговли; отсюда маркет-мейкинг. Прежние подходы (ML на
свечах, ручная торговля BTC) удалены; код — в истории git.
